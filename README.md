# DEADSHIFT

관성으로 몰고, 충돌로 돌파하는 2D 탑다운 차량 좀비 서바이벌. **현재는 Phase 1 플레이어블 버전**입니다. 전체 로그라이트 완성판은 아닙니다.

## 실행

Node.js 24 LTS 권장. 런타임 외부 서비스, API 키, 계정이 필요 없습니다.

```sh
npm ci
npm run dev
```

서버 포트는 기본 5173이며 `PORT`로 변경할 수 있습니다. 데스크톱 Chromium 계열 브라우저와 키보드가 우선 대상입니다. 게임 시작 버튼으로 오디오가 활성화됩니다.

- W / ↑: 가속
- S / ↓: 제동 후 후진
- A D / ← →: 조향 (정지 상태에서는 회전하지 않음)
- Space: 핸드브레이크, 미끄러지며 선회
- Esc: 일시 정지 / 복귀
- 레벨업: 카드 클릭 또는 1 / 2 / 3

좀비를 충돌 또는 자동 조준 기관총으로 처치하고 노란 경험치를 수집하세요. 레벨업 시 차량을 개조합니다. **180초 후 동쪽 좌표 (1150, 0)에 탈출 지점**이 열립니다. 화면의 화살표를 따라 지점 안에 진입하면 성공합니다. 오래 머무를수록 생성 주기가 짧아지고 빠른 적과 중장갑 적이 등장합니다. 벽과 잔해 충돌은 감속과 내구도 손상을 일으킵니다. 정차한 채 좀비에 둘러싸이지 마세요.

## 구조 및 선택

- `src/core.js`: 브라우저와 독립적인 차량 물리, 충돌, 업그레이드, 저장 포맷
- `src/game.js`: 고정 120Hz 시뮬레이션, 렌더링, 전투, 입력 및 화면 상태 전환
- `scripts/`: 의존성 없는 정적 개발 서버와 빌드 도구
- `tests/`: Node 테스트와 Chromium 브라우저 시나리오

자체 Canvas 2D를 선택했습니다. 작은 배포 크기와 단순한 정적 호스팅, 물리 튜닝의 직접 제어가 장점입니다. 엔진의 에디터·충돌 도구·에셋 파이프라인을 직접 구현해야 하는 비용이 있습니다. 게임 런타임은 외부 의존성이 없고 `playwright-core`는 개발 검증에만 사용합니다. 그래픽은 Canvas / 직접 작성한 SVG, 소리는 Web Audio로 생성합니다. 외부 아트·음원·폰트를 사용하지 않습니다.

중량은 가속력과 최고 속도에 영향을 주고 충돌 피해를 높입니다. 기본 차체는 1,200kg이며 충각·장갑·무기는 무게를 더합니다. 같은 장비 선택은 슬롯을 무한 생성하지 않고 그 슬롯을 강화합니다. 현재 지붕 / 전방 / 차체 / 엔진 슬롯만 구현했습니다. 무기는 자동 조준 1종이며, 좌우 방향성 무장·유물·시너지는 후속 작업입니다.

## 검증

```sh
npm run check
npm test
npm run build
# 다른 터미널에서 프로덕션 서버
node scripts/serve.mjs --dist
npm run test:browser
```

브라우저 테스트는 `/usr/bin/chromium`을 사용하거나 `CHROMIUM_PATH`를 지정합니다. 없으면 `npx playwright-core install --with-deps chromium`으로 설치합니다. 테스트는 `?test=1`에서만 노출되는 시나리오 API로 충돌·레벨업·사망·탈출 조건을 설정합니다. 실제 키보드 주행과 렌더링도 검증하지만, 자연 플레이 180초 완주 또는 재미·밸런스 검증을 대체하지 않습니다. 캡처는 `artifacts/phase1-desktop.png`에 생성됩니다.

## 저장

`localStorage`의 `deadshift.save`, 버전 1에 출격 횟수·최고 생존 시간·누적 처치를 저장합니다. 새로고침 후 유지됩니다. 알 수 없는 버전이나 손상된 데이터는 기본값으로 초기화합니다. 브라우저 개발자 도구에서 해당 키를 삭제하면 기록을 초기화할 수 있습니다. 저장이 막힌 경우 결과 화면에 표시하며 게임은 계속 작동합니다. 런 이어하기, 영구 스킬트리, 저장 내보내기 / 가져오기는 미구현입니다.

## 정적 배포

`npm run build` 결과 `dist/`를 정적 호스팅에 올리세요. 모든 앱 리소스는 상대 경로로 로딩하므로 `/deadshift/` 같은 하위 경로에서도 실행됩니다. Node 서버는 개발 도구이며 배포 시 필요 없습니다.

GitHub Pages 배포 준비:

1. 코드를 GitHub의 `main` 브랜치에 푸시합니다.
2. 저장소 Settings → Pages → Build and deployment의 Source를 **GitHub Actions**로 설정합니다.
3. Actions의 `Validate and deploy DEADSHIFT` 실행이 성공했는지 확인합니다.
4. Pages 화면 또는 배포 작업에 표시되는 실제 URL로 공유합니다.

워크플로는 PR에서 검증만, main에서 검증 후 배포합니다. Pages 권한 및 활성화는 저장소 소유자가 필요할 수 있습니다. 클라우드에서 실제 배포는 아직 수행하지 않았으며 공유 URL이 발급되었다고 주장하지 않습니다.
